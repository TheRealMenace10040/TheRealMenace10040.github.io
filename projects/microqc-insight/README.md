# MicroQC Insight

**Live dashboard:** https://therealmenace10040.github.io/projects/microqc-insight/

I built a QC microbiology data model in Power BI, then took it apart and rebuilt it properly. I pulled the raw LIMS tables out of the `.pbix` file, cleaned them in Python the way an analyst would before handing data to anyone, and rebuilt the dashboard as an interactive web page.

All data is simulated LabWare-style LIMS data. No real site data is used.

## The data

- **4,706 results** from Apr 5, 2025 to Sep 26, 2026. The first and last months are partial.
- **Environmental monitoring:** active air and settle plates in 4 cleanrooms, Grade A (ISO 5) through Grade D (ISO 8), across 11 sampling points.
- **Product release:** bioburden and kinetic LAL endotoxin on 80 lots of 3 products.
- **Supporting records:** 55 OOS investigations (29 raised a CAPA), 101 audit-trail corrections, product specs, instruments and LIMS users.

## How I cleaned it

The `.pbix` held 35 tables. 25 of them were Power BI's own auto-generated date tables and the measure table, so I kept the 10 source tables. Then I:

1. **Profiled every column:** nulls, distinct values, whitespace, constants, ranges and date logic.
2. **Removed 3 duplicate results** that were loaded twice.
3. **Fixed timestamps.** Power BI stores dates as floats, so `10:00` came back as `09:59:59.999999786`. Rounded to the minute.
4. **Dropped 16 dead columns:** 9 columns with one value in every row (STATUS is always `A`, PRIORITY is always `ROUTINE`), 5 exact copies of other columns and 2 that were completely empty.
5. **Decoded the LIMS codes:** `SETTLE_PLATE_TSA` → "Settle Plate (TSA)", `skwon` → "S. Kwon", `T/F` → TRUE/FALSE, Grade A → "Grade A (ISO 5)".
6. **Labelled blanks that have a reason.** EM samples have no product, so they read "N/A (EM Sample)" instead of an empty cell.
7. **Built one row-per-result table.** I joined samples, tests, results, investigations and audit trail, checked that every join was 1:1, and **confirmed my OOS, Alert and TAT flags match the original Power BI flags on all 4,706 rows.**
8. **Added fields for analysis:** result status, % of action limit (so different tests can share an axis), turnaround days, past-due and self-review flags.

Every step is in the `Cleaning_Log` sheet of the workbook, with row counts. Every field is defined in `Data_Dictionary`.

## What I found (flagged, not "fixed")

| Finding | Why it matters |
|---|---|
| 779 results (16.6%) were reviewed by the analyst who entered them | Breaks second-person review, a basic ALCOA+ / 21 CFR Part 11 control |
| 41 of 101 audit-trail corrections changed a result from -1 to 0 | A negative CFU count is impossible, so "-1" looks like a placeholder that got past entry |
| 4-day SLA flags 5.2% of results as late, but 43.2% missed their LIMS due date | The Power BI model used a flat 4-day SLA. LIMS due dates are 3 days for EM and 5 for product, so every past-due result was EM |
| Retest Rate and Lab Error Rate always showed 0% | Both Power BI measures were built on columns that are completely empty |
| Sample reviewer and result reviewer disagree on 3,889 records with the same timestamp | Two sources of truth for one event. I used the result-level reviewer |
| 54 of 55 OOS results are Grade A | Expected, since the Grade A limit is 1 CFU and any growth is an excursion. It needs a caption so it doesn't read as a crisis |

## The dashboard

- **Metrics tab:** KPIs, monthly excursions, turnaround by sample type against the SLA, every result plotted against its alert and action limits, investigations and CAPAs by month, results by sample type, on-time rate, excursions by grade and investigation-to-CAPA rate.
- **Data Integrity tab:** self-review rate by analyst, audit-trail corrections over time, turnaround distribution, the two "late" definitions side by side, my findings and the full cleaning log.
- **Filters:** location (carousel), sample type and date range. Every chart and list updates, and the filters are saved in the URL, so **Share** sends someone the exact view.
- **Export** downloads the filtered results as CSV. **Print PDF** prints the current view. The search box looks up any result ID.

## Files

| File | What it is |
|---|---|
| `index.html` | The dashboard (HTML, CSS, JavaScript and Chart.js, no build step) |
| `data.js` | Compact dataset the page loads, generated by the script |
| `clean_microqc.py` | Reads the `.pbix`, cleans it, and writes the workbook and `data.js` |
| `MicroQC_Insight_Clean.xlsx` | Cleaned workbook, ready for Tableau or Power BI: results, lots, investigations, audit trail, specs, instruments, users, data dictionary and cleaning log |

To regenerate: `pip install pbixray pandas openpyxl`, then `python clean_microqc.py MicroQC_Insight.pbix`.

## Built with

Power BI (original model), Python (pandas, pbixray, openpyxl), JavaScript, [Chart.js](https://www.chartjs.org/) and HTML/CSS.
